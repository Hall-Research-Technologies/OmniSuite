2. Files Created on Launch

OmniSuite keeps a small set of local working files so configuration, scan results, and exports survive a restart.

FilePurposeSafe to delete?
config.jsonStores Configuration popup values such as username, passwords, WS port, timeout, concurrency, and firmware path.Yes, but the app returns to defaults and saved passwords/settings are lost.
units_cache.jsonLegacy/current device cache used to repopulate the Device Info list quickly.Yes. The unit list clears until you scan again.
scan_results.jsonUnified scan cache used by Device Info, Configure, A/V Matrix, and USB Matrix. It includes discovered devices plus encoder/decoder route details.Yes. The matrix and configure pages will need a new scan or cache reload.
units_view.csvGenerated inventory CSV used by the Inventory export button.Yes. It is recreated on export.
launcher.logLauncher startup and error log.Yes. It is recreated if the launcher needs to log again.

When running from source, these JSON/CSV files are stored beside the application files. In the packaged app, the launcher log is stored in the user log folder: Windows uses %LOCALAPPDATA%\OmniSuite\logs\launcher.log, macOS uses ~/Library/Logs/OmniSuite/launcher.log, and Linux uses ~/.omnisuite/logs/launcher.log.

Do not edit cache files while OmniSuite is running. Use Clear Units for a normal reset, or close OmniSuite before manually deleting cache/config files.

3. Scanning Units

  1. Choose the network adapter that is connected to the Omni control network.
  2. Leave Targets blank to use the adapter's detected range, or type a specific range such as 192.168.100.1-254, CIDR such as 192.168.100.0/24, or comma-separated IPs.
  3. Click Scan. Discovered units are cached and reused by Device Info, Configure, A/V Matrix, and USB Matrix.
  4. Use the X inside the Targets field to clear manual input and return to the selected adapter range.
On macOS and Linux builds, adapter discovery depends on OS interface data. If the adapter list looks wrong, use the Targets box to enter the intended subnet manually.

Scan results are merged into the existing list. Clear Units removes the current cache when you want a fresh list.

4. Device Info Page

The Device Info page is the fleet overview and firmware workflow page.

Inventory Table

Shows IP, MAC, link speed, codec, hostname, timezone, NTP server, type, model, version, password state, status, blink, preview, and USB information.

Use Show/Hide Device Details to hide or show TimeZone, NTP Server, Type, Model, Version, Password, and USB columns.

Polling

Poll Units keeps status, version, hostname, timezone, NTP server, link speed, password state, and USB feedback fresh without another scan.

Open dropdowns and active edits are guarded so polling does not overwrite the field while you are working.

LLDP Popup

Hover over a MAC address to fetch and show LLDP neighbor data, including switch chassis, management IP, port ID, port description, age, TTL, and capabilities.

Codec

VCx is shown green. Other codec modes are shown red. If the discovered matrix has mixed codec modes, OmniSuite shows a mismatch warning.

Legacy units can change codec. Changing codec reboots the unit and requires confirmation.

Firmware Upgrade

  1. Select one or more units.
  2. Select the firmware file from the firmware selector.
  3. Click Upgrade Selected and confirm the custom upgrade dialog.
  4. Rows move through queued/uploading/upgrading/rebooting/idle based on feedback and version polling.
Some units can time out during upload and need a reboot before retry. The app avoids leaving the UI stuck in an old state, but the device is still the source of truth. Watch for the version to update after the unit returns.

The section switches show or hide groups of columns. They do not disable the underlying device settings.

Configuration import is a device-level restore and can reboot the unit. On legacy units, OmniSuite applies the imported hostname again after reboot because some firmware imports restore other system fields but ignore hostname inside the JSON file.

6. A/V Matrix Page

The A/V Matrix page is for routing. Encoders are columns. Decoders are rows. Click a matrix cell to route the selected encoder to the selected decoder.

ModeWhat it writesVisual feedback
AVWrites video and audio route together.Blue outer ring and black inner dot.
VideoWrites the decoder video route.Blue outer ring.
AudioWrites the decoder audio route.Black inner dot.
Important: the matrix wires decoder video to ip_input1 and decoder audio to ip_input3. When AV is selected, OmniSuite updates both fields. When Video or Audio is selected, it updates only the matching field.

Routes are queued per decoder. You can click multiple decoders quickly; each decoder keeps only the latest requested route while different decoders can process in parallel.

Use Lock Headers when the matrix is larger than the viewport. Use Preview to show or hide encoder preview behavior. Use the encoder and decoder filters to reduce the visible matrix without changing the discovered cache.

7. USB Matrix Page

The USB Matrix page pairs LEX and REX units. LEX units are local extenders, REX units are remote extenders.

  • Click an empty pairing bubble to pair a LEX to a REX.
  • Click an existing paired bubble to unpair it.
  • Pairing feedback may take longer than the physical unit action because the UI waits for refreshed device state.
  • Auto-Refresh keeps the matrix current; adjust the interval for large systems.
USB pairing is layer 2. The control GUI can reach devices across layer 3, but the USB pair itself should be on the same layer 2 network. OmniSuite warns when pairing units on different subnets.

LEX and REX detail tables expose USB type, host port, and filtering settings when supported by the unit.

8. Configuration Popups

Session Popup

Opened from an encoder's Session link on the Configure page. It displays a unit selector at the top so you can move between available encoders without closing the popup.

  • Limited to Session 1 and Session 2.
  • Encoder, DSCP, Downmixing, Source, and Interface are dropdowns.
  • SAP Announce, Scrambling, Video, Audio, FEC, and AUX settings are saved from the popup.
  • Close returns to Configure without applying unsaved changes.

Encoding Popup

Opened from an encoder's Encoding link on the Configure page. It also includes an encoder selector at the top.

  • Shows encoder input, max bit rate, max bit depth, max subsampling, Force YUV, slate mode, slate logo, scaler, and thumbnail controls as supported.
  • Slate modes are off, auto, and manual.
  • Scaler resolution lists are dynamic per encoder. Encoder 1 and Encoder 2 may have different resolution options.
  • If Slate Logo is Not used, slate mode cannot be enabled.

Video Wall Popup

Opened from a decoder's Video Wall Configure button. The popup has a decoder selector so you can navigate between available decoder units while it stays open.

  • Polling is suspended for the edited video wall values while the popup is open.
  • Values are sent only when Save is clicked.
  • After Save, OmniSuite refreshes the selected decoder to verify feedback.
  • In pixels mode, display width and display height are hidden because they are not used.
  • Pixels mode offers incoming source resolution choices: 4K and 1080p. Width and height are populated read-only from that source choice, and the Video Wall Layout control calculates horizontal and vertical coordinates up to 5x5.
  • In inches or millimeters mode, do not apply the pixel math. Width, height, total display width, and total display height are handled as device measurement fields.

Slate Manager

Opened from the Device Info footer. It uploads slate images and applies slate settings to selected units, all encoders, or all decoders.

  • Only .jpg, .jpeg, and .png images are accepted.
  • Images are validated before upload. Use 720 or 1080 resolution assets.
  • A small thumbnail previews the proposed upload before it is sent.
  • Slate delete removes selected slate files from target units when supported by the unit API.
